# Test dataset: synthetic floor plans

This page describes the prepared test plans. "Synthetic" means generated by a
script, not scanned from a real building project. There is no customer, employer
or confidential data here.

## Pairs

12 pairs of plan revisions under `fixtures/aec/<pair_id>/`. A pair is two versions
of the same plan (`a.png` and `b.png`) plus the known correct answer. The settings
and answers are stored as JSON files: a plain-text data format that both people
and programs can read.

| Variant | Pair IDs | Intended change |
|---|---|---|
| identical | `identical-01` | none |
| resize | `resize-01`, `resize-02` | one room grows by 2.0 square metres |
| wall move | `wall_move-01`, `wall_move-02` | one wall moves 20 pixels |
| split | `split-01`, `split-02` | one room split into two |
| merge | `merge-01`, `merge-02` | two rooms merged into one |
| label change | `label_change-01` | label only |
| noise | `noise-01` | scan noise only |
| mixed | `mixed-01` | resize + label change |

Each pair contains:

- `a.png`, `b.png` — 1600×1200 generated plans, where 100 pixels represent
  1 metre, with a scale bar and a title block.
- `config.json` — the `PlanSpec` settings record and the variant name.
- `ground_truth.json` — room outlines, exact areas, centre points and expected
  changes/findings. This is the known correct answer.
- `sam31.json` — recorded model output shaped like Meta's Segment Anything Model
  (SAM) 3.1 response, for both sides. The offline adapter tests use it.

`fixtures/manifest.json` is global, not per pair: it holds a SHA-256 fingerprint of
every generated file in all 12 pairs.

## Scale and units

`px_per_unit = 100` means 100 pixels represent one metre (`units = m`). Expected
areas are computed from the closed outlines; the report must carry both pixel and
real-world units.

## Reproduce

```bash
python scripts/make_plans.py --out fixtures --seed 7
python scripts/verify_fixtures.py --offline --geometry-only
```

The geometry verifier checks the manifest fingerprints, closed outlines, exact
areas and change references. `scripts/run_eval.py` adds the pipeline evaluation
and writes the metrics to `runs/eval/metrics.json`.

## Limitations

- Plans are clean generated line art, not representative scans.
- No OCR (reading text from images), furniture, dimensions or title-block text
  understanding.
- Scale is provided by the settings or a scale bar; it is not inferred.
- No customer data and no real-world accuracy claim.
